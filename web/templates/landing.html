Talos discovery service

A self-hosted discovery service for Talos Linux clusters.

Why is something connecting to this address?

Talos nodes in your organisation use this service to find the other members of their cluster, and with KubeSpan, to set up the encrypted WireGuard mesh between them. Each node keeps one long-lived gRPC connection here and refreshes its entry every few minutes.

What the service can see

Nodes encrypt everything with their cluster's own key before sending it. The service stores and relays that ciphertext but cannot read it. What it does see:

  • the cluster id, a random string chosen by the cluster, used to keep clusters apart;
  • each node's affiliate id, also random;
  • how many nodes each cluster has, and the Talos version each one reports;
  • the source address of each connection, which it hands back to the node as its public IP.

Entries live in memory with the lifetime each node asks for, at most 30 minutes, and disappear unless the node refreshes them. The server can also keep a snapshot on disk so a restart does not lose them.

How it works

Affiliate data is encrypted with AES-GCM. Endpoints are encrypted with AES in ECB mode, which is deterministic, so the same address reported by two nodes is the same ciphertext and the server can merge them without knowing what it is. Every node reports the addresses it sees its peers at; the server merges those, and streams every change to the other nodes of the same cluster, which decrypt it and configure themselves.
